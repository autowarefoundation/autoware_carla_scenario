    Static Check (Codon)¶

    Before a scenario runs, the runner compiles it with Codon, a statically typed compiler for Python syntax, and refuses it when it does not compile. A misspelled method, a str where a float belongs, a condition missing its label, a turn direction passed where a lane-change direction is expected, or a YAML value of the wrong type is reported with the file and line it is on, before CARLA is started:

    $ uv run scenario scenario=intersection_passing/straight scenario.timeout_seconds=fast
autoware_carla_scenario.examples.intersection_passing.IntersectionPassingScenario: static check failed:
  scenario.timeout_seconds: error: 'str' does not match expected type 'float'

    The scenario still runs as Python, exactly as before: the check compiles the same source, never runs what it compiled, and changes nothing at run time. The CARLA API a scenario calls is typesafe_carla, the statically typed CARLA client this framework runs on. A scenario imports it as import typesafe_carla.carla as carla: at run time that is typesafe_carla's CPython package, and for the check it is typesafe_carla's Codon library, so the same names are checked that run.

    Running it¶

    The runner checks every scenario registered with register_scenario() when it builds it, so a run, a batch (scenario='lane_change/*') and every job of a sweep are checked before anything starts. To check without running anything:

    uv run scenario-check                                   # every scenario config
uv run scenario-check scenario=intersection_passing/straight
uv run scenario-check scenario='lane_change/*' scenario.timeout_seconds=20

    scenario-check composes each config exactly as the runner does, so the same overrides apply. scenario='*' is every config, like no scenario=; a package author checks only theirs (scenario='my_package/*', about 15 s per config), as every built-in config takes minutes. It exits with 0 when every scenario passed, 1 when one failed, and 2 when it could not run: there is no Codon compiler, no config matches scenario= (the message lists the configs), or an override names a key the config does not have (scenario.timout_seconds=3 is reported with the closest key, scenario.timeout_seconds; +key=value adds a new one; HYDRA_FULL_ERROR=1 shows the traceback). A scenario package can make the same check in its own tests, with no simulator (the template and scenario-new packages have one in tests/test_typecheck.py):

    from autoware_carla_scenario.typecheck import typecheck_scenario

def test_my_scenario_compiles() -> None:
    result = typecheck_scenario(MyScenario, MyScenarioConfig, {"timeout_seconds": 10.0})
    assert result.ok, result.format()

    When it runs: the typecheck key¶

    Value Effect
    auto (default) Check when a Codon compiler is installed; warn and run unchecked when none is.
    required Refuse to run without a Codon compiler.
    off Do not check.

    Set it like any other key (uv run scenario ... typecheck=required) or with AUTOWARE_CARLA_SCENARIO_TYPECHECK, which takes precedence. A scenario registered with register_scenario_builder() (a custom builder, such as the packages the Scenario Editor exports) is not checked: only its builder knows how it is constructed.

    Keeping verdicts between runs¶

    A process compiles a program once and keeps the verdict for as long as it runs. The program is keyed by its shape: the driver with each config value replaced by its type (a bool, a float, an int, a string, an enum's class), since Codon types it statically and reads no value at compile time. The cases of a sweep that differ only in their values are therefore one program, compiled for the first case and reused, verdict and diagnostics, for the others (logged as "reusing the static check made for the config with the same types"); a failure refuses each of them. scenario-check checks configs side by side, and one whose program is being compiled when it starts waits for that compile rather than starting its own. What changes the shape compiles again: another key or order of keys, a value of another type (an int where the first case had a float in a field not typed float, None where it had a value), another length of a list, a mapping the config converts in one case and not in another. A value whose literal Codon could refuse on its own (an int beyond 64 bits, a string with an escape) is kept as it is.

    Verdicts are kept beyond the process, one file per program, in $XDG_CACHE_HOME/autoware_carla_scenario/typecheck (~/.cache/... without an absolute XDG_CACHE_HOME): a later process with the same inputs reads the verdict instead of compiling. Set AUTOWARE_CARLA_SCENARIO_TYPECHECK_CACHE to use another directory, or to an empty string to keep each verdict for its process only (as happens anyway without a home directory, or with one that cannot be written). A verdict read back is the program's, and is reported for the check that read it (#652): a scenario check's line names that scenario, and a library check's names the modules this run was given and says cached, with the time this run took rather than the compile's. A Codon crash is kept for its process only. A compile that timed out, or a Codon killed with SIGKILL (the out-of-memory killer), is no verdict and is kept nowhere: the next check of the same program, such as the next case of a sweep, compiles it again (#694). Nothing prunes the directory; delete it, or its files not accessed for a while, to reclaim the space. The key covers everything the verdict depends on. For the compile, that is the scenario's (or the framework's) modules, the generated driver's shape, the model, typesafe_carla's Codon library, and the compiler's version and standard library. For the None check, which the scenario, ODD and library checks all run, it is every Python source and stub of the framework, the checker included (mypy reads them for the types of what a scenario calls, and the CARLA stubs are written by its carla_stubs.py from typesafe_carla's Codon library, already in the key), the name and version of every other installed distribution (mypy follows a scenario's imports into numpy, lanelet2 or typesafe_carla), the mypy version, and the Python version. Where a version says nothing of what mypy reads, the files are in it by path, size and modification time: the .py, .pyi and py.typed files of each distribution installed editable and of each directory on MYPYPATH and PYTHONPATH, which mypy searches (a relative entry is taken from the directory the check runs in; symlinked directories are followed). Of the packages being checked, whose modules the key has by their text already, only their stubs count there, so an edit to one scenario of an editable or PYTHONPATH package does not stale the verdicts on the others. And it includes what the checks made in Python found before the compile: an import the framework's Python lacks, or an abstract class that is built. These digests are taken once a process (about 100 ms, more with a large PYTHONPATH such as a ROS workspace's). mypy runs with --config-file= and in an empty directory of its own, so neither a configuration file nor a module of the directory the check runs from reaches the verdict. A scenario package is therefore found as an installed or editable distribution, or through MYPYPATH: give a namespace package (one without __init__.py) an __init__.py, as the scaffolded packages have. What the key still leaves out: a distribution installed in development mode without PEP 610's direct_url.json (an old setup.py develop, a .pth file written by hand); clear the directory after editing one. A crash is never kept, and an entry that cannot be read counts as a miss. A verdict read from the directory has its file's times touched, so the directory can be pruned by access time.

    The test suite shares such a directory between its xdist workers. CI keeps one from run to run, so a run compiles only the programs whose inputs changed.

    Builds wait for their memory¶

    Codon's peak memory grows with what it compiles: about 1.9 GB for a scenario or a module of the framework, about 9.3 GB for the whole library check (2.8 million characters of source). Builds started side by side -- the xdist workers of the test suite, the checker's own pool of four -- would otherwise together outgrow a 16 GB machine, and the out-of-memory killer would take a build (a SIGKILL, above) or, on a CI runner, the runner itself ("The runner has received a shutdown signal").

    So each build first waits for its share (typecheck/memory_gate.py). The builds of a machine record what they hold in one directory ($TMPDIR/acs-codon-gate-<uid>), and one is started when what the running builds hold plus its own estimate fits the machine's memory (or its cgroup's limit) less 1.5 GB, or when none is running: a build too large for the machine still runs, alone. The holds of a process that died are forgotten. Set AUTOWARE_CARLA_SCENARIO_CODON_GATE to another directory to share it differently, or to 0 to start every build at once.

    Installing Codon and typesafe_carla¶

    The check needs typesafe_carla (the typesafe-carla package, from PyPI) and the Codon compiler it pins (typesafe-carla-toolchain, 0.19, which typesafe-carla depends on). Both ship for Linux x86_64 and aarch64, and both are run-time dependencies of the framework anyway: typesafe_carla is its CARLA client (see installation).

    The checker finds Codon the way typesafe_carla's typesafe-codon launcher does (it calls typesafe_carla's own lookup), so one setup serves both: $TYPESAFE_CODON (a codon executable), the typesafe-carla-toolchain package, $CODON_DIR/bin/codon, ~/.codon/bin/codon, then codon on PATH. It runs it with the launcher's environment (CODON_DIR, and LD_LIBRARY_PATH for the bundled runtime). The check is written for Codon 0.19: a Codon of another release series counts as no Codon at all, so auto warns and required refuses. So does a missing typesafe-carla.

    What is checked¶

    The checker copies the scenario's own modules (the module defining the scenario class, its config class, and every module of the same package they import) into a scratch directory, next to a typed model of the framework, and compiles a small program that does what the runner does:

    config = MyScenarioConfig()          # then one line per YAML value:
config.timeout_seconds = 10.0        #   scenario.timeout_seconds
scenario = MyScenario(ego, config=config, spawn_pose=..., ground_projection=...)
scenario.setup()
scenario.is_done()

    A value for a bool, int, float or str field, at the top level as in a nested dataclass, is first passed to a function that takes that type only, on a line of its own (#598): Codon converts any value with __bool__ that is assigned to a bool field, so scenario.enabled=no (which Hydra, like a quoted "false" in YAML, reads as the str "no") would otherwise pass, and the feature would be on. It is refused at scenario.enabled, whether the field has a default or not. An int for a float field still passes.

    Codon checks a function only when something calls it. The program checks everything setup() and is_done() reach: the calls into the framework, the scenario's own helpers, and, through register_pass_condition() and the other register_* methods, the check() of a custom condition and the execute() of a custom action.

    Then it compiles the rest of the scenario's own modules too (#192). Each module the checker copies gets the library check's function appended (What is compiled), and the program calls it after the lines above:

    def _acs_library_check():                      # appended to my_scenario.py
    MyScenario(_acs_value(EgoConfig), _acs_value(Lanelet2Pose), ...)
    _acs_value(MyScenario)._goal_ids(_acs_value(int))    # a helper setup() never calls
    _acs_value(MyScenario).initial_speeds_mps(_acs_value(Optional[carla.Actor]))
    unused_probe(_acs_value(carla.World))                # a module-level function
    _acs_cls_default_9: int = "three"                    # MyScenario.RETRIES: int = "three"

    So an error is reported wherever it is in those modules, not only on the path setup() takes: in a private helper or a public method nothing calls yet, in a hook override the runner calls later (initial_speeds_mps()), in a module-level function, in a class-level default, or in the config class's methods. Each call passes a value of each parameter's annotated type, and a defaulted parameter's default is compiled by one more call that leaves it out.

    The result of a hook override is checked against the framework's type (#238). Codon compiles an override against its own annotation only, and the framework code that calls it is a stub of the model, so check() -> bool, initial_speeds_mps() -> list[float] or is_done() -> str compiled, and failed or misbehaved when the scenario ran. So each appended call of a method passes its result to the model, which checks it strictly against the return type of the method it overrides, when the class derives from BaseScenario, BaseCondition, BaseAction or EgoVehicle (directly, or through a built-in condition or another class of the scenario's modules):

        _acs_hook_return(MyScenario, "is_done", _acs_value(MyScenario).is_done())
    _acs_hook_return(GapCondition, "check",
                     _acs_value(GapCondition).check(_acs_value(carla.World), _acs_value(float)))

    Every method and property each of the four classes declares is such a hook, with the return type the model declares for it (test_typecheck_model.py keeps the two in step): setup() returns None, is_done() a bool, initial_speeds_mps() a Dict[int, float], check() an Optional[ScenarioResult], execute() None, debug_markers() a DebugMarkers, and so on. The check is strict where an annotated assignment is not (Codon 0.19 converts any value with __bool__ in done: bool = x): an override must return the type itself or what Python's typing takes for it -- a subclass of a class, an int for a float, a bool for an int, and, for an Optional[X], an X, an Optional of one, or only None (a condition that never decides). A str, an int or an Optional[bool] for a bool is refused, at the override's def line:

    scenario.py:62: error: BaseScenario.is_done() returns bool, and this override returns another type
    reached by <scenario check: MyScenario.is_done()>
    during the realization of _acs_expect_return(r: str, T: bool, ...) [scenario_base.codon:230]

    A method of a class deriving from none of them, or one its base does not declare (a helper of the scenario), is not checked this way, and neither is an abstract one (@abstractmethod) or one that only raises (raise NotImplementedError()): it returns no value, which Codon types None whatever its annotation says. The program also checks what the scenario's own setup() and is_done() return, after the module checks, for one the appended calls leave out.

    A wrong call or return is reported in the author's terms (#527, #528,

    529, #530). Codon says `no function 'SetSpeedAction.init' with arguments¶

    (SetSpeedAction, EntityRole, str, str)for a call it cannot match, and'float' does not match expected type 'str'(the two types swapped) for areturnof the wrong type. The check reads the call or thereturn` in your file, binds it to the real Python signature of the class, method or function, and says what is wrong, at the argument:

    scenario.py:28:62: error: SetSpeedAction(): target_speed_kmh: expected float, got str
scenario.py:28:60: error: TimeoutCondition(): 'lable' is an invalid keyword argument (did you mean 'label'?); TimeoutCondition takes (timeout_seconds: float = 60.0, *, label: str)
scenario.py:36:9: error: val() returns str, but the function is declared -> float

    A message that cannot be tied to a parameter is X() takes (...); got (EntityRole, str, label=str), with self dropped and a keyword argument marked. A static string type prints as 'str' (not ''3''), the frames of the model's own helpers (_keyword_only, _required_str, actions.codon) are left out of the trace, and a literal None given where a type is expected is told that the parameter does not take None rather than to test the value.

    Some common slips get a hint after Codon's message (#599), each only where both the message and your source at the line say it is that slip:

    You write Codon says The hint
    range(len(ids) / 2) range() cannot be called with (float) range() takes ints, and / always gives a float: divide with //, or convert with int()
    ids[len(ids) / 2] __getitem__() cannot be called with (float) an index must be an int: divide with //
    ",".join(ids) of a list[int] 'Generator[int]' does not match expected type 'Generator[str]' ",".join(map(str, ids)) or ",".join(str(v) for v in ids)
    self.register_pre_tick(lambda: None) (also register_post_tick, register_init, a register_measure read function, a register_cover expression, or a def of no parameter) a lambda() takes 0 arguments (1 given) the callback is called with the world: lambda world: ...
    self.register_measure("flag", lambda w: True) expected a float (or an int) names the measure and what its read function returns (a bool is no number to a measure: 1.0 if ... else 0.0, or a cover)

    A range() or index of a float without a / written there, and a join of something that is not a call of join at that column, get none.

    Two declared return types Codon does not enforce are refused from the syntax, before Codon runs (#529): a return of a literal, an f-string or a display in a function declared -> bool (Codon converts it to a bool; Python returns the str), and a function declared to return a type other than None, Optional[...], Any or NoReturn whose body can run off its end. The flow analysis follows if, while, for, try, with and match; a while True without a break, a raise, assert False, sys.exit() and a call of a function declared NoReturn end a path, and a body that is only ..., pass or a docstring (an abstract method, an overload) is not checked. A returned expression whose type is not obvious from its syntax (return some_str) is not judged.

    Then mypy checks that an Optional is tested for None before it is used (#239). Codon unwraps an Optional[T] implicitly wherever a T is needed, so cfg.min_speed_kmh / 3.6 of a float | None field compiled, and raised TypeError in Python when the field was None. After the compile, the checker runs mypy (a dependency of the framework) over the scenario's own modules, following imports silently, checking the bodies of unannotated functions too, and with no configuration file of the package's (so the verdict does not depend on how strict the package's own mypy settings are), and keeps only what it reports of a value that may be None used where it may not be: an attribute of it, an operator, an argument, an assignment, a return, an index, or an item of a list or dict display (mypy's union-attr, operator, arg-type, assignment, return-value, index, call-overload, list-item and dict-item; a set display's item is an arg-type to mypy), each only where None is the offending type (#267): the None item of a union an attribute is missing on (Item "None" of "Waypoint | None"), an operand, the value indexed or an argument that is None or a union holding it, or a value whose type holds None given where the type expected does not (incompatible type "float | None"; expected "float"), the key or the value of a dict entry included (Dict entry 0 has incompatible type "str": "float | None"; expected "str": "float"). An item matters because Codon unwraps it where the model iterates the sequence (#308): register_cover(..., buckets=[0.0, 10.0, cfg.min_speed_kmh]) and register_cross("c", ["speed", maybe_name]) compiled, and failed in Python on the None; [0.0, x or 0.0] passes. A message that only mentions None inside another type or in the type expected is not one: a reader returning Optional[str] given to register_measure(), which takes one returning Optional[float], is a str for a float, Codon's error to report, and a list[float] for a list[float | None] is mypy's invariance, which Codon accepts. An assignment that only declares is not one either: a None default for a non-Optional annotation (speed: float = None), or a value assigned to an attribute mypy inferred as None from its first assignment. Each finding fails the check at its line, after Codon's errors:

    scenario.py:67:28: error: Unsupported operand types for / ("None" and "float"): Codon unwraps an Optional implicitly, so test the value for None before this use, or Python fails here when it is None (mypy: operator)
    Left operand is of type "float | None"

    The same pass refuses a framework union used as one of its members (#309). Codon holds TrajectoryVertex.position (a TrajectoryPosition, the union of the ten poses) as a Union, and converts it to whichever member a use needs at run time (No attribute of a union, below), so v.position.lanelet_id of a MapPose vertex, or v.position passed to a parameter typed Lanelet2Pose, compiled, and raised AttributeError in Python. mypy reports both (union-attr, arg-type), and the pass keeps them where the union mypy names is made of the members of one of the unions the model holds: each module-level Name = Union[...] alias of typecheck/codon/autoware_carla_scenario/ (TrajectoryPosition, AnyPose) and each property it declares to return a Union[...] (TrajectoryVertex.position, CoverItem.event), read from the model, so the list follows it (none_check.framework_unions(); test_typecheck_none_check.py checks each against the union Python declares). mypy reports a missing attribute once per member lacking it; the check reports it once, naming them all, with its own advice:

    scenario.py:71:27: error: Items "CarlaWorldPose", "OpenDrivePose", "MapPose", ... of "CarlaWorldPose | Lanelet2Pose | ... | RouteRoadsidePose" have no attribute "lanelet_id": Codon holds this union of the framework's (TrajectoryPosition) and converts it to the member this use needs at run time, so narrow it with isinstance first, or Python fails here on any other member (mypy: union-attr)

    Narrowed code passes (if isinstance(p, Lanelet2Pose): p.lanelet_id), and so does the union passed on where the union is taken (TrajectoryVertex(v.position, advance=v.advance), a TrajectoryPosition parameter).

    A field of a frozen dataclass of your own is read-only (#567). Codon compiles a frozen dataclass as an ordinary class, so mypy's verdict is used: p.x = 2.0, p.x += 1.0, self.x = ... in a method of the class, a loop variable's field and a frozen subclass's field are refused as Pt is a frozen dataclass; use dataclasses.replace(x, x=...), where the receiver's type is known to mypy (a value of unknown type, Any, is not). dataclasses.replace and object.__setattr__(self, ...) in __post_init__ stay valid. The class is found by its name: a name is treated as a frozen dataclass only where every class of that name in the scenario's modules is one (a same-named plain class with a read-only property is left alone, at the cost of a missed frozen assignment). The decorator may be @dataclass(frozen=True, ...), @dataclasses.dataclass(frozen=True) or an aliased import. This rests on mypy, as the None check does: without it the check warns the None check did not run and a frozen assignment is not reported. setattr(p, "x", 1) is not caught.

    bytes and str do not mix (#574). Codon's bytes is a str, so b"x" + "y", "sent " + name.encode(), a bytes returned for a -> str, passed to a str parameter or assigned to a str, "x" in raw and raw == "ab" compile, and Python raises TypeError (or the comparison is always False). They are refused with mypy's verdict, only where the offending pair is exactly bytes and str: bytes and str do not mix in Python: decode with .decode() / encode with .encode(). A str | bytes union, a bytearray and every other incompatible type are left alone, and b + b, s + s and .encode() used as bytes stay valid.

    A comparison that is always False is refused (#575). The None check runs mypy with --strict-equality and keeps its comparison-overlap findings: an Enum member compared with its raw value (Color.RED == "red", mode == 1, mode in (1, 2)) or with a member of another enum is False in Python, and Codon compiles it. The advice is an Enum member never equals its raw value: compare with Color.RED, or use Color.RED.value. Only the findings with an enum as an operand are kept, not every comparison-overlap: mypy also reports two different literals (MODE: Final = 1 and if MODE == 2), a deliberate switch. The enum is found among the classes of the scenario's own modules (an enum imported from elsewhere is not recognised, so its non-literal comparisons are missed). mypy skips a class that defines __eq__, and IntEnum, StrEnum and (str, Enum) overlap their raw value in Python as well, so Level.LOW == 1 and Phase.GO == "go" are valid. Color.RED.value == "red" is the valid spelling. A member written out as a literal (Level.LOW == 1) is judged by mypy on identity, so it is kept only for a plain Enum / Flag defined in the scenario's own modules, and two members of one enum (Color.RED != Color.BLUE) are not a comparison with a raw value. The flag adds no other error, so the None check's other findings are unchanged; the framework's modules and the built-in scenarios have none of these comparisons. Like the rest of this section it rests on mypy.

    A string formatting Python fails on is refused (#589). The None check keeps mypy's str-format findings of a str.format call or a % on a literal format string where Python raises at the call: a conversion the value does not take ("{:d} km/h".format(speed) for a float and "{:.2f}".format(name) for a str raise ValueError, "%d km/h" % name and "%x" % speed raise TypeError), too few or too many arguments ("%s %s" % (name,), "{} {}".format(name)), a missing named field or mapping key, an unknown format character or conversion ("%q", "{!x}"), a malformed spec ("{:abc}", an unmatched {), and mixing automatic and manual field numbering. Codon formats with its own rules and compiles all of them. The advice is Python raises ValueError, TypeError, IndexError or KeyError on this format string with these values (...); convert the value first (int(x), str(x)) or use "{}" / "%s". "%d" % speed (a float) and "{:.2f}".format(n) (an int) are valid, as in Python. A conversion the value does not take is kept only for a built-in type that fails for every value (str, float, None, bytes, complex, a list, ...): mypy does not count a class's __index__ ("%x" % obj runs) or a __getitem__ without keys ("%(k)s" % obj runs), and refuses "{:.2f}" of a complex or a Fraction, which run. Too many arguments is kept only for a % whose right operand is a tuple display or a constant: "{}".format(a, b) ignores the extra argument, and "abc" % d formats no key of a dict (or of a list, or bytes). An unknown spec is kept where the Python running the check refuses it ("{:z.1f}" runs on 3.11). Three more of mypy's str-format messages are not kept, because mypy gives them to valid code as well: Numeric flags are only allowed for numeric types ("{:05}".format(name) runs; "{:+}".format(name) does not, and the message does not say which flag), Syntax error in format specifier and the field-accessor ones ("{0[my key]}".format(d) and "{0['k']}".format(d) index d with "my key" and "'k'"). An f-string's spec (f"{speed:d}") is not checked: mypy does not check it, and rewriting it into a .format call for mypy would move the columns mypy reports. Like the rest of this section it rests on mypy.

    Typing contracts you declared must hold (#577). Python mostly does not enforce these and Codon does not read them, so mypy's verdict is used, each kept only on its exact code and message (no other misc, override, index or attr-defined error is a finding; Codon reports attribute errors itself):

    • Final assigned again (MAX_SPEED: Final = 30.0, then MAX_SPEED = 40.0, self.LIMIT = 40.0, Cls.LIMIT = 1.0 or a Final local rebound): a name declared Final is bound once; .... Bind a new name or drop Final.
    • A ClassVar assigned through an instance (self.count += 1, c.count = 5): a ClassVar is shared by the class; .... Python creates a shadowing instance attribute and Codon treats the annotated name as an instance field, so what runs can differ. Assign through the class (Cls.count += 1) or drop ClassVar.
    • A method incompatible with the one it overrides: a narrowed argument type, a different return type, a required parameter added, or a parameter removed (the override must accept what the overridden method accepts ...). This covers the framework's hooks too: BaseScenario.is_done(self) -> bool overridden as is_done(self, strict: bool) is refused, since the framework calls it with the base signature. An extra parameter with a default, or a wider argument type, is fine, and # type: ignore[override] on the def line (mypy's own) silences it. The dunder methods are not checked (__eq__(self, other: Pt) is common and benign), nor is a method overriding object's. The built-in scenarios and the template produce none.
    • A Mapping, Sequence or AbstractSet mutated (m["k"] = 1, del m[k], s.append(3), s.sort(), m.update(...), a.add(1)): ... is read-only by its annotation; copy it first .... Only an attribute that mutates (append, extend, insert, pop, remove, sort, reverse, clear, update, setdefault, popitem, add, discard, the set *_update methods, __delitem__) on a receiver typed exactly as one of those three counts; a typo (s.appnd) or a missing attribute of another type is not reported here. Import them from typing or collections.abc (read as typing's, #586; its Set is AbstractSet): the check is the same.

    Not checked: a name bound on one path only (#576). Python raises UnboundLocalError for if c: y = 1 followed by use(y), and mypy reports it only with --enable-error-code possibly-undefined. That code is not enabled: mypy's flow analysis cannot see that the branch that binds a name and the branch that reads it test the same condition (if x is not None: v = ... then if x is not None: use(v)), nor that a for over a non-empty constant runs, so valid code is refused and the cure is to restructure correct code. Run over the framework's 313 modules it reports 15 times in 11 modules: 9 are a condition tested twice or a try/with that binds on every path that reads, 4 are a loop mypy cannot see always binds (a for over a non-empty constant, a for/break/else), and 2 are latent edge cases in the framework (an unbound exit_code when server.cooldown_max_retries is negative, and an unbound port_file in slurm/worker.py's finally when layout.task_port raises after the port slot was taken), not scenario patterns. Probes of scenario-style branches showed the same: if/else, an exhaustive enum if/elif, try/except that raises or returns, match with a default and for/else pass, but a loop variable read after a for and a guard tested twice are refused. Bind the name before the branch when you mean to read it later.

    The CARLA API's Optional results are checked too (#267). typesafe_carla's CPython package is a prebuilt extension with no .pyi and no py.typed, so mypy alone reads typesafe_carla.carla as Any. The checker gives mypy stubs of it instead, written from typesafe_carla's own inventory of its Codon library (typesafe_carla.pycarla.Inventory, which the CPython package is generated from; typecheck/carla_stubs.py) and put on MYPYPATH: every public class with its bases, and every method and property with the return type the library declares. So Map.get_waypoint(), ActorList.find(), World.get_actor(), World.try_spawn_actor(), Actor.parent, Vehicle.get_traffic_light(), Waypoint.get_left_lane(), Sensor.poll() and the library's other Optional results are Optional to mypy, and a use without a test for None is refused like a float | None config field:

    scenario.py:76:16: error: Item "None" of "Waypoint | None" has no attribute "transform": Codon unwraps an Optional implicitly, so test the value for None before this use, or Python fails here when it is None (mypy: union-attr)

    get_waypoint() is the one exception to the library's declarations: it returns None when no lane of lane_type matches, and projected onto the road (project_to_road=True, its default) that is only on a map with no such lane at all, so the stubs give that call a Waypoint (the framework uses it unguarded too). With project_to_road=False, or a flag mypy cannot read as True, it is Optional. The stubs type only what the None check needs: parameters are *args: Any, **kwargs: Any (the arguments are Codon's to check), and a return type mypy cannot be given (a pointer, a type parameter, overloads returning different types), an enumeration, carla.command and any name not written are Any, so they add no error of their own. They are written once per library, under ~/.cache/autoware_carla_scenario/carla-stubs/ (named by a digest of the library's Codon sources), or into a temporary directory where that cannot be written; where typesafe_carla's library cannot be read, mypy runs with CARLA untyped, as before.

    Narrow the value first, as mypy reads it: if x is not None:, assert x is not None, an early return when it is None, or a default (x or 0.0). mypy keeps a cache in ~/.cache/autoware_carla_scenario/mypy (under $XDG_CACHE_HOME when it is set), so only the first check reads the framework (about ten seconds); where that directory cannot be written, as in a container with a read-only home, mypy runs without a cache. A scenario package installed as a wheel (not editable) is checked too: mypy would take site-packages for its source root, so the check gives it the package through a link in a directory of its own. When mypy gives no verdict (it ran out of time or crashed), the check keeps Codon's verdict and says so in a warning:

    warning: the None check did not run (mypy did not finish within 600s), so an Optional used without a test for None is not reported

    The error is reported at the scenario file's own line. One in a function's body is at that line, with the call that reached it in the trace:

    scenario.py:88:16: error: 'MyConfig' object has no attribute 'timeout_secs'
    during the realization of _helper(self: MyScenario) [<scenario check: MyScenario._helper()>, scenario.py:87]

    One in what the appended line compiles itself is at the line of the class-level default, or, for a parameter's default, at the def of its function, and the trace names the call (reached by <scenario check: class-level default of MyScenario.RETRIES>).

    A function the check cannot call, because a parameter has no annotation, one Codon cannot express (Any, object, Callable[..., R]) or one naming a TypeVar (a generic function), is not refused: it is left out of the appended calls with a warning, and compiled where setup() and is_done() reach it, generically, as before. So is one whose return annotation names Any, such as a custom condition's get_details() -> dict[str, Any] of mixed value types, which Codon cannot build (the library check lists the framework's own as uncalled):

    my_scenario.py:40: warning: MyScenario._scaled: parameter `x` has no annotation; the check does not call it on its own, so it is compiled only where the scenario's constructor, setup() and is_done() reach it

    A helper with a **kwargs or a *args that the scenario calls is compiled through those calls (#266). The appended calls give a *args: T one T and a **kwargs no keyword at all, and Codon types each from the call: a Tuple[T], an empty NamedTuple. So def opts(**kw: float) reading kw["speed"] was refused ('NamedTuple' object has no attribute 'speed', reached by <scenario check: opts()>) although setup() calls opts(speed=2.0), and xs[1] of a *xs: float likewise. Such a function whose body reads what they hold (kw["speed"], xs[1], a, b = xs, g(*xs), g(**kw)) and that a function, a class body or the module's top level of the scenario's modules calls (by its name: opts(...), self.scale(...), helpers.opts(...), Tuner(...) for its __init__; its own recursive call does not count) is not called again: its callers' calls compile it with what they pass. One whose body does not read them (kw.get("speed", 1.0), sum(xs)) is called as before: a call is known by its name only, so a gains.update(p=1.0) would otherwise leave a helper update to a call of dict's, and nothing would compile it. One nobody calls is still called, so an error in it is found, unless it subscripts its **kwargs, which no call without a keyword compiles: that is left out with the warning above (MyScenario._opts: reads**kwby key, and nothing in the scenario calls it: the check has no keyword to call it with).

    A warning does not fail the check (result.ok stays true; they are in result.warnings), and scenario-check and the runner print them. Annotate the parameter to have the function checked on its own. Refusing such a function would have refused a scenario that passed before, for a helper that compiles wherever it is called. No built-in example, the scenario package template or a scaffolded package has one.

    An ODD written in Python (ODD) is checked the same way: the program calls its builder (odd: OddDefinition = urban_odd()). Every attribute's probe is then called with a world, and every condition must come from an attribute. The ODD's own modules have every function compiled as a scenario's do, with the same warning for one the check cannot call (compiled where the builder reaches it). The runner checks the ODD named by the odd key under the same typecheck mode, and scenario-odd check does it without running anything.

    The model¶

    autoware_carla_scenario/typecheck/codon/ holds Codon declarations of everything a scenario imports from autoware_carla_scenario: the conditions, actions, poses and coordinate functions, entities, BaseScenario, the shared config dataclasses, with their static types. The CARLA API is not modelled: the checker puts typesafe_carla's Codon library next to the model, the way typesafe-codon puts it on CODON_PATH, and import typesafe_carla.carla as carla (the import the runtime uses) resolves to it, so a scenario is checked against the whole typed CARLA API. typesafe_carla's Python-API compatibility shortcuts (such as calling a Vehicle method on a plain Actor) compile, as they do outside strict mode. Nothing in the model runs; test_typecheck_model.py keeps each declaration it compares in step with the Python definition of the same name (parameter names, order, defaults, keyword-only parameters, methods, enum members): every name __init__.codon exports, the names the checked modules or a scenario import from the model beside those (_BOUNDARY), and every name of the model modules that stand for one framework module each (_MODULE_MODELS), which must declare exactly the names compared, beside model-only helpers named _acs_* (the list below). metrics.codon and measures.codon are two of those: each declares the whole of its module's __all__, and the test also compares by value their constants (the keys, VEHICLE_AHEAD_VERSION, the distances and speeds the vehicle-ahead measures read with), each built-in entry of BUILT_IN_METRICS (title, unit, text, aggregation) and of BUILT_IN_MEASURES (unit, text, version), the field types and defaults of Metric, Measure and Bumpers (frozen dataclasses, so @tuples: assigning to a field fails the check, as it fails the run), and the parameters of Metric's and Measure's __new__. Only a built-in's read differs: Python's is a private function of the module, which no scenario can import, and the model's a stub (_acs_unread), since nothing in the model is read. Metric(), Measure() and BaseScenario.register_measure() take any read a world can be passed to that returns a float, an int, None, or an Optional of a float or an int -- a function returning float, lambda world: None -- as Python's do, and refuse any other return type (a str, say) at the line that passes read, with "expected a float (or an int)". The three share that check (_reader.codon, outside measures.codon, which imports scenario_base), and Measure is defined there too, so BaseScenario.measures can return a Dict[str, Measure]; measures.codon re-exports it. Metric() and Measure() store the stub: a Codon Callable field takes a function of its exact type only, and Codon 0.19 crashes on any other. set_measured_scenario() takes a scenario of any BaseScenario subclass or None, which Python annotates Optional[BaseScenario]: Codon's Optional takes no subclass.

    register_pre_tick(), register_post_tick() and register_init() take an Optional action or callable (#537): Codon does not narrow an Optional after if a is not None:, so the value registered there is still one, and the model unwraps it (None itself is refused). A reader that is maybe_float or 0.0 is a Union for Codon and passes the reader check (#538). An Optional of a subclass held where its base is declared (c: Optional[BaseCondition] = ElapsedTimeCondition(...), or an Optional[BaseCondition] helper parameter) is Codon's to refuse, in the scenario's own code (#541): the message says to declare it without Optional. to_lanelet2() is one untyped definition, as to_carla_world() is, because Codon tries only the last of two typed overloads; test_typecheck_model.py fails on a model function defined twice.

    An actor is checked by kind for the same reason (#278). follow_with_spectator() and log_actor_position() take a getter Python types Callable[[], Optional[carla.Actor]], and initial_speeds_mps() an Optional[carla.Actor]. Each takes a carla.Actor, any subclass of it (carla.Vehicle, carla.Walker, carla.Sensor, ...), an Optional of one, or None. A getter returning a carla.Vehicle is the natural one to pass, because typesafe_carla keeps a vehicle's controls on carla.Vehicle. Codon 0.19 refused an Optional[carla.Vehicle] for an Optional[carla.Actor], so these parameters are generic in the model. The model's _expect_optional_actor unwraps the Optional and upcasts a class of a hierarchy to carla.Actor, the way a hook result is checked. Anything else is refused at the call, the framework's EgoVehicle (lambda: self.ego_entity) included:

    scenario.py:70:9: error: BaseScenario.follow_with_spectator(): the getter must return a carla.Actor (or a subclass of it, such as carla.Vehicle), or None

    register_cover()'s values= and ignore=, and OddAttribute(values=), are checked as openodd uses them (#279). values= must be None, an iterable (a list, a tuple, an empty one too, a set, a str, a range) or an enum class, the framework's (values=TurnDirection) or the scenario's own.     Writing a scenario that type-checks¶

    A scenario is ordinary typed Python. Codon is stricter than Python in a few places, and the checker smooths over most of them (it rewrites X | None into Optional[X], drops @dataclass (and appends the ==, ordering and hash it generates) and resolves field(...) defaults, accepts keyword-only parameters, required ones after a default included (a call that passes one by position is refused at the call, as Python refuses it: gap() takes 1 positional argument but more were given: scale is keyword-only,

    622), gives a list of different conditions the type¶

    list[BaseCondition], checks a tuple[X, ...] return annotation as a List[X], drops a parameter or return annotation naming a class the module defines further down, which Codon cannot name yet, gives a subclass that keeps its base's __init__ that __init__, and types the return None of a function returning Optional[X]; see below). What a scenario has to do itself:

    • Import its own modules from its own package. A module of the scenario's package imported as a module works (#310): Codon 0.19 resolves from X import name only as a name X/__init__ defines, and an absolute import a.b only from the importing file's directory, so the checker rewrites, on the same line, from . import helpers, from pkg import helpers and import pkg.helpers as helpers in pkg/scenario.py into import helpers as helpers, and from .sub import mod into import sub.mod as mod. A module outside the importing module's package (from .. import helpers in pkg/sub/scenario.py, or import pkg as p) has no such form, and neither has one imported without a name (import pkg.helpers, which binds pkg): each is refused at its line, naming the form that works, which is to import the names (from ..helpers import speed_kph) or to name the module (import pkg.helpers as helpers):
    scenario.py:3: error: `from .. import helpers` imports the module pkg.helpers as a module, which Codon 0.19 resolves only inside the importing module's own package (pkg.sub): import the names instead (`from ..helpers import name`)

    • from .helpers import * binds helpers.__all__. When the helper module of the scenario's package sets __all__ as a literal list or tuple of strings, the checker rewrites the star import into an import of those names, on the same line (#506), so a scenario that uses a public name __all__ leaves out is refused (name 'SPEED' is not defined) as Python raises NameError. An __all__ built any other way is not read: the star import then binds every public name of the helper.

    • Import a name once. Python accepts from autoware_carla_scenario import ComparisonRule in the import header and again further down, and so does the check (#354): Codon 0.19 leaves a module-level name imported twice undefined in every module but the one it compiles first, so a use of it failed the whole function with a bare "cannot typecheck". The checker drops a module-level import that repeats an identical earlier one (the same module and name, under the same alias), on its line: the repeat becomes pass, or loses just the repeated names. An import in a function or an if is left as written. A name imported from two different places (from a import X, then from b import X) means the later one in Python: the checker drops the earlier import when nothing reads the name in between, and refuses the later import, naming the first, when something does:

    scenario.py:12: error: `ComparisonRule` is imported again from somewhere else (first on line 5) after it was used, which Codon 0.19 cannot compile: import each name once, under its own name (`import ... as other` to tell two apart)
    • Declare the attributes it assigns on self, at class level, with their type:
    class MyScenario(BaseScenario):
    _config: MyScenarioConfig

    def __init__(self, ego_config, spawn_pose, config=None, ground_projection=None):
        super().__init__(ego_config, spawn_pose=spawn_pose, ground_projection=ground_projection)
        self._config = config or MyScenarioConfig()

    A bare annotation is ignored by Python, so this changes nothing when the scenario runs; Codon needs it to type an attribute of a subclass. The check names each undeclared attribute and suggests its type.

    Declare them in every class of the scenario's modules, helper classes included (#218). The check refuses an undeclared attribute of a class with a base, a subclass, or at least one class-level annotation: once a class declares one attribute, Codon gives it only those it declares. A plain class that declares none has its attributes inferred from its __init__, which Codon cannot always do: not for self._samples = [] (a list of nothing yet), and not in a method the scenario check calls on its own (What is checked), on a value its __init__ did not build ('int' does not match expected type 'NoneType', during the realization of get(self: Counter[NoneType])). Codon's error is then at a line of the helper, or names the attribute holding the helper, not the helper (type of attribute '_tracker' of object 'GapCondition' cannot be inferred), so the check adds, for that helper, each attribute it assigns without declaring it, at its line, with the type to declare:

    scenario.py:34: error: GapTracker._samples is assigned without a type: declare it in the class body, e.g. `_samples: list[...]` ...

    And assign each attribute you declare (#588). Codon gives every field its zero value when the object is built, so a declared attribute nothing assigns reads as 0 (or "", an empty list) in the check, and Python raises AttributeError at its first read. The check refuses a bare class-level annotation (no default; not a dataclass, NamedTuple, TypedDict or Protocol field, nor a ClassVar) that a method of the class or of a subclass reads (self._count, self._count += 1: an augmented assignment reads first) when nothing assigns it, at the annotation:

    scenario.py:41: error: CountCondition._count is declared but never assigned: Codon zero-initialises it, and Python raises AttributeError where a method reads self._count; assign self._count in CountCondition.__init__, or give it a default (_count: ... = <value>)

    The rule is conservative: the attribute counts as assigned when any module of the scenario stores an attribute of that name, on any object and in any form (self._count = 0, self._count: int = 0, self.a, self._count = ..., setattr(self, "_count", 0), object.__setattr__(self, "_count", 0), other._count = 0), when a framework base assigns it (the base's source, or the framework assigning it from outside; for a mixin, when the framework bases of every scenario class deriving from it assign it: class VehicleInfoMixin: ego_config: EgoConfig mixed into a BaseScenario, but not when a class Plain(VehicleInfoMixin) derives from it too), and when the class or a base gives it a value (a class attribute, a property). A class that assigns attributes by a computed name (setattr(self, name, v), self.__dict__, vars(self)), defines __getattr__, or derives from a class outside the scenario, the framework and the built-ins is left alone.

      error: Codon failed without a diagnostic: exit status -11

A Codon killed with SIGKILL (exit status -9: the out-of-memory killer, as when two library checks of about 8 GB each run at once) is no crash of the code: the check says so, names no local, and should be run again with more memory free. Like a timeout, it is not kept as the verdict, so the next check of the same program in the process compiles it again (#694).

A local that is only ever None and that a conditional expression tests (z = None, then z + 1 if z is not None else None, even 1 if z is None else 2) crashes Codon 0.19 with no diagnostic; the check names it after the crash, at the conditional expression.     • A @dataclass compares, orders and hashes as Python's does: the check appends == and != (eq=True, the default), <, <=, > and >= (order=True) and hash() (frozen=True, or unsafe_hash=True) after the module, comparing the fields in order (a dataclass base's first; field(compare=False) and ClassVar are left out; InitVar and KW_ONLY cannot be imported in the check, see "Standard library names Codon lacks"). Codon's parser ends the field there and reports a position that is no line of your file. Bind the value to a local first (label = "{:>3}".format(x), then f"{label}"). A syntax error Codon still reports inside an f-string field is shown at the line of the f-string that has it (the first f-string with a format spec, else with a literal brace, else the file's only f-string line), with no column, and never at a line before the file: with no one f-string to blame, it is shown with no line rather than at a guessed one.
    • A type error inside an f-string field is shown at the f-string's line, with no column (#610). Codon reports it on the line after the line the f-string starts on, at the faulting expression's column plus the length of the field's text: a column past the end of that line, or no line of the file when the f-string is on its last line. The check moves such an error back when nothing on the reported line starts at the reported column, of any width (Codon locates an error on that line itself there; its width of a call on several lines counts the characters across the line breaks, that of a with or for statement is one more than Python's), and an f-string that starts on the line before has a field holding an expression of that width that ends at or before the column (and, on a one-line f-string, no further from it than the f-string's end). The line shown is the expression's own (a field on a later line of a triple-quoted f-string is shown on its line). An error of the line itself always has such an expression (a comprehension's for c in n clause, which Codon locates from its for, is matched by where it ends), so it stays where it is, column and all. An implicitly concatenated f-string ("a" f"b{n + 'x'}", also on several lines, #616) is reported on the line after its first literal's line too, at a column the bound above does not hold for: the first literal's 0-based column, plus the offset of the field's { in its own literal, plus the field's length, plus the expression's offset from the {. The check computes that column for each field of an f-string that starts on the line before (a triple-quoted literal, a field on several lines and a line that is not ASCII excepted) and moves an error that matches it, column and width, to the field's line, with the same guard (anything that starts on the reported line at that column keeps it).
    • A class constant read in the class body (#433): Python resolves the name in the class scope, Codon in the module's (name 'LIMIT' is not defined), so the check writes Class.LIMIT. It rewrites exactly what Python resolves there: a name an earlier assignment of the same body bound, read by another statement of the body, a dataclass field default, a method's parameter default or a decorator. A method body, a lambda body and a comprehension (but for its first iterable) do not see the class scope, so a bare LIMIT there is the module's and stays; a nested class sees only its own body; a parameter or comprehension variable named LIMIT shadows nothing at the default, which is read in the class scope. In an Enum a member read by a later statement is its value in Python (B = A makes an alias), so the check writes the literal; any other name of the body is qualified as above.
    • The constant has to be a class attribute in Codon. A name annotated at class level (LIMIT: int = 5, Final[int], ClassVar[int]) is a typed field of the instance, not an attribute of the class, so a read of it cannot be qualified: when its value is a single-line literal the check writes that literal where the name is (n: int = 5; Python reads the same value), and otherwise the read is refused with a hint: write LIMIT: Final = 5 (a bare Final is dropped, leaving a class attribute) or no annotation, or use a module-level constant. A NamedTuple field default cannot read its own class constant either (x: int = LIM is "no module named"): its other statements and methods can.

The exception is a Callable[[A], R] parameter whose function body stores it (self._cb = fn, self._cbs[key] = fn, self._cbs.append(fn), or hands it to a method of the same class that stores it, self._add(fn)), with argument and result types Codon can express: it is kept, written as Codon's Callable[Tuple[A], R], so a callback registry (a class-level _cbs: list[Callable[[int], int]] that register() appends to) has the same type on both sides. A parameter the body only calls, or passes on, stays dropped, so a closure still checks. An optional callback (Optional[Callable[[A], R]], Callable[[A], R] | None) is kept the same way when the body stores it, written as the plain Callable[Tuple[A], R] (Codon converts a function, a lambda and None to it, but a function or a lambda to an Optional of it not), the = None default staying.     • A Codon abort with std::bad_alloc names the Callable attributes of the checked modules at their lines; a function passed where a Callable of another signature is expected is named at the call that passes it (Codon 0.19 reports no type error for that, only a code generation failure).
    • cast(T, x) is x typed as T (as in Python, nothing checks that x is a T); when T cannot be named in Codon (a Callable, a class defined further down) it is x as it is.
    • A class-level Y: Final[int] = 4 stays a typed field, not a class attribute, as any annotated class-level name does; write Y: Final = 4 for a class attribute read as C.Y.     • Iterator is Codon's generator type, and Deque, DefaultDict and Counter are collections.deque, defaultdict and Counter.
    • Any other name is refused at its import line. Generic and TypedDict cannot be modelled: leave the type parameters of a class or function unannotated (Codon makes it generic over them) instead of subclassing Generic, and write a @dataclass (or a Dict[str, X]) instead of a TypedDict.

    What Python raises for that Codon compiles (#602, #603)¶

    Codon checks types, so a call it compiles may still raise in CPython. Three kinds are decided from the syntax and refused at the call, before Codon runs (typecheck/static_raises.py):

    • sum() with a str start (#625): sum(["a", "b"], ""), sum(parts, start="-"), a start that is an f-string or str(...), and likewise a bytes or bytearray one.     • isinstance / issubclass with a subscripted generic (#603): isinstance(v, list[int]), issubclass(C, dict[str, int]), isinstance(v, typing.List[int]), also inside a tuple of classes ((str, list[int])), a | union (int | list[int]) or a typing.Union / Optional. When every argument of a call is a literal (a constant, or a tuple, list, set or dict of them, by position or by keyword) and the callee is imported from the framework, the check builds the class with those literals and reports the ValueError it raises, in the framework's own words:

    • x in Mode and x not in Mode;
    • Mode["A"], a member looked up by name.

    Inside the enum's own methods the class has other spellings, and the check reads them as the class (#481). In a @classmethod, the first parameter (cls, or whatever it is called) is the class, so [g.name for g in cls], list(cls), len(cls), x in cls and cls["A"] work. In an instance method, type(self) and self.__class__ are the class too (for m in type(self)). These hold only in a method written directly in the class body: a @staticmethod, a function outside the class and a class that is no enum are left alone, and so is a parameter the method rebinds (an assignment, a loop or comprehension variable, an import, a nested def), a nested function or lambda that declares a parameter of the same name, and a type the module or function binds.

    Iteration yields the members in definition order. A member whose value repeats an earlier one is an alias, and is skipped, as in Python. A Flag or IntFlag yields its single-bit members only, as Python 3.11 and later do: a composite (RW = R | W, BOTH = 3), a zero member and an alias are skipped, though Perm["RW"] finds them. Only the name of the class (and the spellings above) is rewritten, so a parameter or local called like the class is left alone, and the enum may be defined in another module of the package.

    The framework's enums are @tuple classes in the model (typecheck/codon/). Each declares _acs_members() and _acs_by_name(), and the check takes the enums to rewrite from the model files, so a new model enum is iterable once it declares them. test_typecheck_model.py keeps both equal to the Python enum's members, in its order. A scenario class of the same name as a model enum that is no enum is left alone, and so is a module-level variable, function or non-framework import of that name (#471); a parameter or local of the name shadows it only inside its function.

    What does not work:

    • the class under another name or as a value: k = cls and then for m in k, or f(cls), and cls.__members__. They stay as written (the first is refused with a hint to write the class's name: 'Mode' object has no attribute '__iter__');
    • the class passed as a value, f(Mode), or Mode.__members__: both stay as written, which Codon does not resolve (no function 'List.__init__' with arguments (List[T], type[Mode]) for list(e) in f, and 'Mode' object has no attribute '__members__');
    • sum, any and all of the class, and filter(None, Mode): Codon needs __bool__ or + on the member (sum(int(m) for m in Mode), any(m == x for m in Mode));
    • an enum with no member ('Empty' object has no attribute '_acs_members').

    Flag and IntFlag¶

    A scenario's own Flag or IntFlag (also class M(int, Flag)) combines as in Python: A | B, &, ^, ~ and A in x (every bit of A is set in x) make a value of the same class, an IntFlag takes an int on either side too (P.R | 4, 4 | P.R), and bool(x) is false for no bit set. Two combinations of the same members are equal, hash alike and compare equal to the member that has their value (P.R | P.W == P.RW). A Flag does no other arithmetic, order or int(); an IntFlag compares, orders and converts as an IntEnum does, and P.R + P.W is refused (use .value). ~x flips the bits of the single-bit members for a Flag, and every bit up to the highest of any member for an IntFlag, as Python 3.11+ does. The operators are usable at module level and in a class body or default (RW = P.R | P.W).

    A combination is no member: the check builds it from the combined int, so it has an empty name, and P.R | P.W is P.RW is not modelled (compare with ==). A value written as an expression of the class's own members, even a composite or an auto() one, is worked out when the check reads the class (RW = R | W, ALL = A | B | C, HIGH = 1 << 4, ALL = ~0); auto() is the power of two above the highest bit so far. Operators of two different flag classes, and of a framework enum such as TurnDirection.LEFT | TurnDirection.RIGHT (not a Flag, so Python refuses it too), are refused.

    What the check does not catch¶

    The check compiles the scenario and never runs it, so it says nothing of what a value is at run time (a division by zero, a missing key, an actor that is not spawned yet), and it accepts some code that fails in Python. The known gaps:

    • An Optional unwrapped implicitly, where mypy cannot see it. Codon unwraps an Optional[T] wherever a T is needed (arithmetic, an attribute, an argument), and mypy's pass (#239, What is checked) catches what mypy can type, CARLA's results included (from stubs of typesafe_carla's Codon library, #267). It does not see a value mypy reads as Any: one from a package with no type information (an import it cannot follow, which it ignores, such as lanelet2), a CARLA result whose type the stubs leave Any (an enumeration, carla.command, a pointer, a method whose overloads return different types), or the result of a function with no return annotation. Neither does it check the arguments of a CARLA call: an Optional passed to one is Codon's to unwrap (world.get_actor(maybe_id) compiles).
    • A union of the scenario's own classes used as one of its members. The None check's pass refuses only a union made of the members of one of the framework's (#309, What is checked): a union of classes the scenario defines (a class-level tuple[A | B, ...], held as List[Union[A, B]]) is converted at run time as Codon converts any union, and an un-narrowed use of one member's attribute compiles.
    • An attribute set on some paths only. Codon zero-initialises every field, and the class rules (#587, #588) follow no paths: an __init__ that calls super().__init__(...) in one branch only, or an attribute assigned in a method that may run after its first read, compiles and can raise AttributeError in Python. A class that is not a module-level name (one defined in a function) is not given the rules at all.
    • A helper with **kwargs or *args that nothing calls and that reads **kwargs by key is not compiled, with a warning: the check has no keyword to call it with (#266). One the scenario calls that reads them is compiled only with the keywords and the number of values its callers pass, and, as a call is known by its name only, not at all when the only calls of its name are another's (d.update(...) for a helper update) or are in a function the check does not compile.
    • A value converted by an annotated assignment. Codon 0.19 converts any value with __bool__ in an annotated assignment: done: bool = "no" compiles, and is True. (A literal returned from a function declared -> bool is refused, #529.) The check binds hook results strictly (#238) and class-level bool defaults through _expect_bool (#190), but an annotated local of the scenario's own code is converted as written. A local x: bool = some_str is no bool in Python.
    • An int where a float is expected is accepted, in a call and a hook result alike, as Python's typing takes it; not inside a container ([1, 2] for a list[float] is refused).
    • A function the check cannot call (a parameter with no annotation, or one of Any, object, Callable[..., R] or a TypeVar, or a return annotation naming Any) is compiled only where setup() and is_done() reach it, with a warning (What is checked).
    • A hook a class takes from a mixin listed before its framework base (class Gap(CheckMixin, BaseCondition), with check() defined in CheckMixin) is compiled as the mixin's own method, not checked against the hook's return type: define the override in the class itself.
    • A None default is not checked against its annotation: speed: float = None is an Optional[float] to Codon (mypy, in the scenario package's own pre-commit, reports it; the None check reports only its uses).
    • What only a tuple does: a tuple[X, ...] is checked as a List[X], so its hash, its equality with another tuple and its immutability are not checked.
    • An int is 64 bits, and no value is computed (#613): Codon's int is a 64-bit integer, and the check compiles the code without running it, so an overflow (2**64, math.factorial(25)) and 2 ** -1 (a float in Python) assigned to an int are not caught.
    • bytes is read as str: path.read_bytes() + "text" compiles, and CPython refuses it.
    • A values= that only Codon iterates (register_cover(), OddAttribute, #279). Codon 0.19 cannot tell a class passed as an argument from one of its objects, so an enum member passes where an enum class is meant (values=TurnDirection.LEFT). A frozen dataclass of the framework (a @tuple, so iterable to Codon) passes too, and so does an element type expression never returns.
    • An enum member looked up by value (ActionState("completeState")) is typed, but not resolved to the member. Lookup by name and iteration work for a scenario's own enum, within the limits of Iterating an enum.
    • typesafe_carla's Python-API compatibility shortcuts (a Vehicle method called on a plain Actor) compile, as they do outside its strict mode.
    • A scenario registered with register_scenario_builder() is not checked at all: only its builder knows how it is built.
    • The None branch of a conditional expression chosen statically (#629). The check makes Codon decide a if x else None (and None if x else a) from x's type (#597): where x is always None to Codon, only the None branch is compiled. When the test does not narrow as Python does (None if x else x.a, which evaluates x.a exactly when x is None), the error in the other branch is not compiled. mypy's pass reports it where x is annotated (Item "None" of "Npc | None" has no attribute "a"); an unannotated parameter only ever given None passes.
    • A sum() whose str start is a variable (sum(parts, sep)), which CPython refuses: only a start written as a string, an f-string or str(...) is decided from the syntax (#625).
    • A value a framework constructor refuses, unless every argument of the call is a literal and the class is one of those built with literal arguments (#602): MetricCondition(cfg.metric, label="m") with an unknown metric, or any other framework class, raises at setup().

    Checking the framework itself¶

    The scenario check trusts the model: it never compiles the framework's own source. The library check does, a module at a time, as each is made to compile:

    uv run scenario-check --library                                   # every checked module
uv run scenario-check --library autoware_carla_scenario.kinematics.vector

    from autoware_carla_scenario.typecheck import typecheck_library

result = typecheck_library()  # the modules typecheck/library.py lists as checked
assert result.ok, result.format()

    test_typecheck_library.py makes the same check in the test suite.

    The checked modules get the None check too (#277), as a scenario's modules do: after the compile, mypy runs over every module the run compiled, with the CARLA stubs, and an Optional used without a test for None fails the check at its line. Codon unwraps an Optional in the framework as it does in a scenario, so the compile alone accepted CollisionCondition reading CollisionEvent.other_actor (None for a collision with map geometry) as a carla.Actor, and the sensor callback raised in Python:

    conditions/collision.py:158:32: error: Incompatible types in assignment (expression has type "Actor | None", variable has type "Actor"): Codon unwraps an Optional implicitly, so test the value for None before this use, or Python fails here when it is None (mypy: assignment)

    It adds about 11 seconds to a run with mypy's cache cold, and under a second with it warm, to a compile of about a minute. A verdict kept between runs (below) holds the None check's too: the key already covers what it reads. test_typecheck_none_check.py runs the same None check over CHECKED without Codon, so a machine without a Codon compiler catches it as well.

    So do the class rules (#587, #588): before the compile, the library check imports each module it compiles and refuses an __init__ that skips a base's (any class of the package counts as the framework here) and an attribute declared at class level that nothing assigns, as the scenario check does (Writing a scenario that type-checks). A module that does not import in Python has its classes left alone. test_typecheck_class_rules.py runs both rules over every module of the package without Codon.

    A run that names modules is a slice of the full run. With the named modules, it compiles from their source the CHECKED modules they import, transitively. It does not follow an import that MODELLED_IMPORTS routes through the model, or one inside an UNCALLED function. It also brings the other modules of a REPLACED_MODELS entry once one of them is in, so that the model re-exports the checked definitions, as it does in the full run. scenario_base, for example, imports register_vehicle_entity from the checked entity.registry, which the model does not declare, and entity._spawn holds the checked GroundProjectionConfig, which the model VehicleEntityConfig must share. The modules it imports are checked as fully as the named ones: their functions and methods are called too, and errors are reported for every compiled module, not only the named ones. An error in a module the named one imports is an error the full run reports as well, and it would stop the named module from compiling anyway. Hiding it would only make the run fail without a reason. The result's title gives both counts (1 checked modules, 44 more they import for scenario_base, at the time of writing). Run without names, the check compiles exactly CHECKED, as before. Every checked module passes on its own.

    The check's driver imports the model before any checked module, whichever module it names first. The model reaches the checked coordinate.frames through _poses.codon, and a run that started at coordinate.frames would reach the model, and come back to coordinate.frames, before that module defines anything.

    The manifest: typecheck/library.py¶

    CHECKED lists the modules compiled from their source; EXCLUDED maps every other module to the reason it is not. "not yet checked (#45)" marks a module nobody has made compile yet; any other reason names what keeps a module out ("imports omegaconf, hydra": a package or a standard module Codon cannot compile). numpy is not one: Codon ships its own, and a module's numpy calls compile. Every module of the package except typecheck/ is in exactly one of the two, which the test suite checks, so a new module needs an entry.

    UNCALLED names the few functions and methods of a checked module the check leaves out (module.Class.method, or module._helper for a protected one), each with its reason: one whose job Codon cannot express, in a module that otherwise compiles, such as what builds a condition's details (a dict[str, Any] of mixed value types) or reads a config node of any type (What is checked of the framework below lists every entry). Codon compiles a function only when something calls it, so neither its body nor an import made inside it is compiled: a module that needs a package or a standard module Codon lacks for one function imports it inside that function (import yaml in constraints_from_text()) and lists the function here. (json is not one of them: its shim, typecheck/codon/json.codon, writes any one-typed value and reads opaquely; what keeps to_json() out is the mixed-type dict it writes.) A test checks that every entry names a function or method of a checked module.

    To check one more module:

    1. Move its entry from EXCLUDED to CHECKED. CHECKED holds one module a line, sorted (a test keeps it so), so the move is one line removed and one added, each where no other pull request's lines are.
    2. Run uv run scenario-check --library and fix what it reports, in the module. Only annotations and Codon-friendly rewrites: the module must behave exactly as it did. A function that cannot compile gets an UNCALLED entry, one line, with its reason.
    3. Run uv run pytest autoware_carla_scenario/test/carla_scenario/test_typecheck_library.py.

    This page needs no edit: the counts and the lists of What is checked of the framework are generated from typecheck/library.py when the docs are built (mkdocs_hooks/typecheck_library.py, #789). A checked module is listed with the first paragraph of its docstring, so give it one that says what the module is.

    What is compiled¶

    Codon checks a function only when something calls it, so the check appends a function to each checked module that calls every function and every method of every class (constructors, static and class methods, properties and their setters, dunder methods, protected _ ones and those of _ classes included) with a value of each parameter's annotated type:

    def _acs_library_check():
    normalize_angle_deg(_acs_value(float))
    Vector3(_acs_value(float), _acs_value(float), _acs_value(float))
    _acs_value(Vector3).dot(_acs_value(Vector3))

    _acs_value(T) is a T Codon cannot tell from a real one; nothing compiled is ever run. A parameter annotated with a union (Lanelet2Pose | OpenDrivePose, Union[BaseAction, Callable[[carla.World], None]], or an Optional of one, Optional[Union[EntityRole, str]]) is called once with each member, so the body is checked for every type it accepts. A parameter with no annotation, or one Codon cannot express (Any, object, Callable[..., R], Callable[[Any], Any], ...), gives the check nothing to call with and is reported as a problem of the module, at its line: annotate it with the type its callers pass. The exceptions are other: object in __eq__ and __ne__, which Python requires, called with the class itself, and a parameter Codon cannot express that has a default: a function whose every such parameter has one is called only leaving the defaults out (Defaults are compiled too, below), so its body is compiled with them (#199). A Callable whose argument and result types Codon can express (Callable[[carla.World], Optional[float]], a dataclass field too, or an Optional of one) is called with a value of Codon's Callable type, which a function of that signature converts to. One with a union among its argument types (Callable[[Optional[Union[EntityRole, str]]], CarlaWorldPose], the reference lookup of trajectory.resolve) is no type Codon 0.19 can hold: it crashes on it ("union already sealed"). Such a parameter is called with _acs_Returning[R, N] (_tc.codon), a callable that takes N arguments (as many as the Callable does) of any type and returns an R, so the body is compiled with the number of arguments it passes checked, their types unchecked, and with what it gets back checked.

    A *args: T is given one T (run_uv(cwd, *args: str, ...) is called with one str), so the body is compiled for it; one with no annotation, or of object or Any (__exit__(self, *args: object)), is given nothing.

    A method with keyword-only parameters or **kwargs is called through its class (TrafficBackend.start(_acs_value(TrafficBackend), ..., skip_actor_ids=...)): Codon 0.19 calls a method a subclass may override through a dispatch thunk, which takes neither a keyword argument nor **kwargs, and the call through the class checks the same body.

    Defaults are compiled too (#183). The calls above pass every argument, so no default was ever compiled: find_nearest_traffic_light(..., max_distance: float = "far") passed the check. A function or method with a defaulted parameter is now called once more, with only the arguments that have no default, each of its first type:

        find_nearest_traffic_light(_acs_value(carla.World), _acs_value(Lanelet2Pose))
    AutowareBridge.configure(_acs_value(AutowareBridge), _acs_value(BridgePose), _acs_value(BridgePose))

    A method is called through its class (AutowareBridge.configure(...), not _acs_value(AutowareBridge).configure(...)): a dispatch thunk fills in no default, and through it AutowareBridge.configure() and FakeAutowareBridge.configure() do not compile. A *args: T is still given one T (run_uv(cwd, *args: str, timeout: int, env=None) with one str and timeout), so the positional parameters before it are passed, defaulted or not: without it run_uv() does not compile. A function with no default gets no such call. An error in a default is reported at the call, which names it (<library check: find_nearest_traffic_light(world: carla.World, location: Lanelet2Pose), with the default ofmax_distance>: error: 'str' does not match expected type 'float').

    Checked modules and the model¶

    The checked modules are compiled next to the same model the scenario check uses. Every import of the framework in a checked module is pointed at what stands in for it in the check's workspace:

    • another checked module: its own (rewritten) source;
    • any other module: its model, the codon/autoware_carla_scenario/ module of the public package it belongs to (coordinate.poses is modelled by coordinate.codon), or, for a module of a package that is itself checked, a model of that module alone (utils/traffic_light.codon, autoware_bridge/grpc_server.codon, driver/egodriver_client.codon, maps/cache.codon, autoware_stack/devcontainer.codon, ros2/cyclone.codon), or, for a module of the top-level package, a model of that module (carla_install.codon, for server, declares installed_executable(); trajectory_recorder.codon, for scenario_runner, the TrajectoryRecorder it starts, records and closes, whose JSON lines hold values of mixed types; environment.codon, for scenario_runner, capture() and the id of the RunEnvironment it returns; weather_rules.codon, for visibility and actions.environment, the weather_range(), vehicle_range() and vehicle_rules_in_use() they read the weather rules through). A module with no model (utils.config) cannot be imported by a checked module until it is checked itself.

    Each checked module gets the __file__ Python sets on it (its source's path, a str), which Codon 0.19 does not, bound on the last line of the prelude so it exists before any code of the module and no line moves (#515), so Path(__file__).resolve().parent / "data" and os.path.dirname(os.path.abspath(__file__)) compile at module level and in a function: autoware_stack.bridge_node finds the installed autoware_bridge package with from ..autoware_bridge import __file__. Codon has no module object, so from .. import autoware_bridge and autoware_bridge.__file__ do not compile.

    Two checked modules that import each other can each need the other's types the moment Codon reads it: BaseScenario declares _measures: dict[str, Measure] at class level, and measures declares the running scenario (_MEASURED: dict[str, Optional[BaseScenario]]) as a global, so neither can be read first. MODELLED_IMPORTS in typecheck/library.py breaks such a cycle: the module it names (measures, entity.ego) imports the other (scenario_base) through its model, as it did before that one was checked. Its types are the model's, which never meet the checked module's. The egos derived from EgoVehicle (entity.bridged_ego, entity.autoware_entity) do not override EgoVehicle.spawn(), so they never name EgoConfig and need no entry: Codon 0.19 cannot call super().spawn() through an intermediate class ("'EgoVehicle' does not match expected type" in its dispatch thunk), and an override that repeated the spawn instead would take scenario_base through the model as entity.ego does. Through the checked scenario_base, a run with an example scenario in it failed in Codon 0.19's code generation (LLVM: error: value doesn't match function result type '{ ptr, ptr }', in opt_ref_new of the model's BaseScenario).

    A model module that stands in for unchecked code declares only what the checked modules and scenarios use of it. coordinate.codon still declares, of coordinate.projection, the map_origin(), resolve_projector() and _parse_geo_reference() that coordinate.map_manager and sweeper.map_loader import, though the library check now compiles all three from their source. Its MapManager is now the scenario check's alone: the library check compiles map_manager.py from its source, which every checked module imports, and nothing of the model takes or returns a MapManager, so it needs no REPLACED_MODELS entry.

    A checked module is compiled under a name of its own (_acs_lib.autoware_carla_scenario__coordinate__frames), since Codon reads the workspace's packages only from .codon files and names a file in its errors by its base name alone; errors are reported at the line of the real source file. A type a checked module defines is not the type the model declares under the same name, so a checked module cannot hand its own value to a model function that wants the model's: check modules bottom-up, before the modules that use them.

    Where the model's functions take the types a checked module defines (the poses, which to_opendrive takes and returns), the model's own declarations of them live in a model module of their own (_poses.codon), which REPLACED_MODELS in typecheck/library.py names with the modules it models. Once those are all checked, the library check compiles that model module as a re-export of their definitions, so the model and the checked modules share one Lanelet2Pose. A name the model declares that none of the checked modules defines is reported.

    Conditions: the checked base and the model¶

    conditions.base is checked, so the checked conditions derive from the real BaseCondition (_acs_lib.autoware_carla_scenario__conditions__base), not from the model's. The two are different types that never meet:

    • the scenario check compiles a scenario against the model only; no checked module is in its workspace, and the model's BaseCondition, _expect_condition and _acs_list (which recognises a condition by the model-only _acs_condition marker) are unchanged;
    • the library check compiles the checked conditions against the checked base. A checked module that hands a condition to a model function (an unchecked action) cannot do so until that module is checked too (scenario_base is checked, and imports BaseCondition from conditions.base for that); _acs_list gives a list display of checked conditions the type of its first element (_acs_base leaves a checked condition in a dict display as it is), so a display mixing two checked condition classes waits for the same.

    BaseCondition.__init_subclass__, which wraps every subclass's check() to record its last result for the UI, is in UNCALLED: the check sees each check() as written.

    actions.base is checked the same way: a checked action takes the checked BaseCondition, so it imports it from conditions.base rather than from the conditions package, which the model stands in for until it is checked. Its BaseAction and ActionState are again not the model's, so conditions.action_state watches checked actions. An action that hands its base a condition of its own making imports that condition from its checked module too (SetSpeedAction's default SpeedCondition from conditions.composition.speed); one whose module is not checked waits for it.

    Making a module compile¶

    What Codon 0.19 needs that Python does not, beyond the rewrites above:

    • Write an iterator class's __iter__ as a generator (#504): Codon has no __next__ protocol, so for k in Countdown(3) over a class whose __iter__ returns self is refused (expected iterable expression, with a hint). def __iter__(self): while self.n > 0: self.n -= 1; yield self.n compiles, and is valid Python too.

    • A dict display holds one value type (#505): {"a": 1, "b": "x"} is refused even annotated dict[str, Any] (Codon has no usable Any or Union value). Convert the values to str, use a dataclass with typed fields, or use one dict per type. The base-class annotation of #489 is for the scenario's own subclasses only.

    • Annotate what the check calls: every parameter of a function or method it calls, protected (_) ones included, with a type Codon can express. Spell a union out (Lanelet2Pose | OpenDrivePose) rather than through an alias (AnyPose); a union with object or Any in it gives nothing to call with.

    • A default must have the parameter's type (#183): the check compiles each function once with its defaults. A () default of a sequence parameter is checked as an empty List[X], so X must be a type Codon can express and name there: a class defined further down the module is not (the () is left as it is, and fails). A None default of a dropped Optional is typed only for a sequence or a Callable the check can call with; Optional[Callable[..., R]] and Optional[Mapping[K, V]] stay a bare None, so a body that uses them past an is None test fails. A tuple display default (= ("a", "b")) of a sequence parameter is checked as a list of its elements, List[X](["a", "b"]), as a dataclass field's is (#188); a fixed-length Codon tuple is no List[X]. An empty [] / {} default of a list[X] / dict[K, V] parameter (or [] of a sequence) is checked as an empty one of that type; Codon would make it a list of None. A None default is not checked against its annotation: Codon makes speed: float = None an Optional[float], which passes (mypy, in pre-commit, reports it).
    • Declare attributes on any class in a hierarchy (exceptions included) and on a class with __slots__, at class level (_value: str).
    • A class-level default is compiled as written (#190): the library check assigns it to a local of its annotation in its own function, which the transform does not rewrite. So a default the transform would rewrite in a dataclass (a tuple display or () of a tuple[X, ...] member, frozenset()) is reported: assign such a value in __init__ instead. A default naming another member of the class (TWICE: float = LIMIT * 2), or anything else its body binds, is not checked, as at the function's scope the name is not the member; neither is a None default, which Codon makes an Optional of any annotation (x: float = None compiles). An override without an annotation (REISSUES_BY_DEFAULT = True) is checked against its base's annotation only when the base is a class of its module or of a checked one.
    • hasattr() instead of getattr(x, name, default): Codon decides hasattr when it compiles, so the branch for a type without the attribute is never compiled. The check rewrites getattr(x, "name", default) so itself where the name is a literal and x a name or an attribute chain (#590, "Python the check rewrites for Codon").
